### 2.1 ⚠️ 真機驗證延後 + 完整測試腳本（使用者明確要求，**非選項**）

**裁決**：**真機測試等到功能完整（T-033c 上線後）再一次做完**，並且交付時**必須提供完整測試腳本**。

**理由**：多場並行在 T-033c 之前不對使用者開燈（開團入口仍擋第二場），此刻只能驗單場零回歸——
等於同一批人要為同一個功能被拉去測三次。

**連帶規則**：
- **T-033a／T-033b 各自上線後不再要求真機驗證**，改由機器關卡 + R2 雙審把關。
- `真機驗證` 這一項的 DONE 條件**統一掛在 T-033c**；T-033c 未附合格腳本 = 未完成。

**腳本規格（使用者要求「完整」，請照這個標準做）**：

1. **可照著一路打完，不需回頭讀任何設計文件。** 每一步明確寫出：**要打的字**（逐字，可複製）
   與**預期回覆**（逐字，含標點）。不要寫「檢查是否正常」這種要讀者自己判斷的句子。
2. **含前置設定**：需要幾個 LINE 群組、幾個帳號（主辦 / 一般成員 / 非授權者 / super-admin）、
   每個群組要先開幾場什麼樣的活動（場地／日期／時間要指定，因為 `@selector` 的比對規則吃這些）。
3. **涵蓋 T-033a~c 全部功能**，至少包含：
   - **單場零回歸**：`名單`／`+1`／`-1`／`開團`（逐步 + 一行式）／`編輯 日期·時間·場地·費用`／
     `分組`→`下一輪`／多行批次。**含 `@隨便打的文字 +1` 在單場時應照常成功**（AC-6，最易寫錯處）。
   - **多場並行**（T-033c 開燈後才可測）：無指定 → ambiguous 提示；`@場地` 命中一場；
     `@場地 日期` 組合；日期不夠精準時加時間窄化；命中 0 場／>1 場的兩種錯誤回覆。
   - **quote（引言）**：T-033b 後才生效。引用某則 bot 訊息 + `+1` 應作用到該場。
   - **授權作用對象**（AC-23）：A 場 host 甲、B 場 host 乙，甲下 `@B場地 取消活動` 應回非授權。
   - **開團查重與上限**（T-033c）：同場地+時間重複開團被擋；同群 open 第 4 場被擋。
   - **跨群不外洩**：引用他群訊息應視為未引言，不得洩漏他群資訊。
4. **每項標註對應的 AC 編號**（子文件編號，如 `[D-023 AC-8]`），讓失敗時能直接對回設計。
5. **標明哪些項目在哪個相位才可測**（T-033a 可測 / T-033b 後 / T-033c 後），避免測試者在功能還沒開燈時
   誤判為 bug。
6. **附「預期不會發生什麼」**：例如單場時不該出現任何消歧義提示、`下一輪` 不該要求 `@selector`。
