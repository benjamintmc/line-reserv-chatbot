## 5. 需要 reviewer 特別留意的地方
1. **`src/db/schema.ts` 的 `ConversationStateRow.group_id: string | null` → `string`**：D-013 未明列此項，但 0004 之後該欄已 NOT NULL，型別不改會使 `grouping-service.nextRound` 的 `groupId: conv.group_id` 編譯失敗。我選擇「讓型別反映 schema 真相」而非改用 `input.groupId` 繞過。若審查認為應維持 row 型別不動，請指示改回。
2. **`withAbandonedNotice` 我採 AC-5② 的「去參數」選項**（而非把參數收斂成 `AbandonedKind`）——好處是字面型別與死分支一次消失，代價是 handler 端 `result.abandoned !== undefined ? withAbandonedNotice(base) : base` 讀起來略怪（`abandoned` 純作為存在旗標）。
3. **AC-6 我以「靜態掃描測試」而非一次性 grep 落實**（`d013-conversation-scope.test.ts`）：可重跑、防日後漂移，但代價是測試碼裡有字串/括號掃描邏輯（含一處 `if (f.endsWith('d013-conversation-scope.test.ts')) continue;` 自我排除，因本檔含 needle 字面值）。若認為過度工程，可退回單次 grep + 移除該檔靜態部分。
4. （附帶）`event-claiming-static.test.ts` 的 `[D-006 AC-13]`「零 migration」與 `migrate.test.ts` 的 migration 計數是既有硬編碼清單，因新增 0004 而必須更新——屬 AC-7 語意下的機械式更新，非行為回歸。
