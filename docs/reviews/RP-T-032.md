1. **三個真缺陷的修法與「是否曾假通過」的判定**（重點）：
   - `list-formatter.test.ts` fixture 補 `price_mode: 'per_person'` / `venue_fee: null` / `settled_per_person: null`。
     **舊行為未被掩蓋**：`list-formatter.ts:76` 判 `event.price_mode !== 'split_venue'`，缺欄位時值為 `undefined` ⇒ 也走 per_person 分支，
     補上真實值後執行路徑不變、**未動任何斷言**（477 全綠可證）。
   - `handler.groups/security.test.ts` 移除 `RegistrationServiceDeps.runInTransaction` 與 `EventServiceDeps.{registrations,processed}`。
     已逐一核對兩個 constructor：這些屬性**從未被讀取**（`RegistrationService` 用的是 `runImmediate`，測試本來就有正確傳），
     故屬「多餘的注入」而非「該注入卻沒注入」，**沒有守衛被靜默 noop、沒有假通過的斷言**，不必改斷言。移除後與 `handler.test.ts:45` 的既有寫法一致。
   - `scripts/seed-open-event.ts` 原本傳 `eventDate`/`eventTime`（D-008 之前的舊欄位），**該腳本自 D-008 起就是壞的**（`event_datetime` NOT NULL 會炸）。

2. **`import.meta` 的處理方式**：`pool-ssl.test.ts` 改用 `join(__dirname, '..', 'index.ts')`，與同 repo 既有寫法一致
   （`metrics-sql.test.ts:14` 早已用 `join(__dirname, ...)` 且在 vitest 下正常運作）。**沒有**為此放寬 test tsconfig 的 `module`——
   維持與生產同樣的 `commonjs` 語意，避免型別檢查與 build 的模組解析出現落差。
