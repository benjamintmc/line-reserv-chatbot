## 5. 需要 reviewer 特別留意的地方

**5-1（architect-reviewer）`feeLabel` 造成 domain → formatter 的一條 value import。**
`event-service.ts:47` `import { feeLabel } from './event-formatter'`。這是本 repo 中 domain 對 formatter 的**唯一**執行期依賴（其餘方向皆為 `import type`，無執行期循環）。**這是 D-019 §一.3／§一.5 的字面規定**——設計文件明文把 `feeLabel` 定義為「formatter 內部 helper」，backend-engineer 依文件實作、未擅自更動位置。請裁定：接受此偏離（並在 D-019 補 errata 記明），或要求把 `feeLabel` 下移至 domain／共用模組。

**5-2（兩位）AC-7 的證明方式與文件字面不同。**
D-019 AC-7 原文要求斷言「未呼叫 `updatePricePerPerson`／`updateVenueFee`」。實作選擇的是更強的做法：**兩個舊原語已從 `event-repository.ts` 整個移除**（`grep -rn "updatePricePerPerson\|updateVenueFee" src/` 僅命中一行說明註解），型別層面不可能呼叫到，故未再寫 `not.toHaveBeenCalled()`（該方法已不存在，寫不出來）。請裁定此等價性是否成立。

**5-3（design-reviewer）新 `bad_fee` 文案與 D-005 §6.2 的措辭刻意不逐字同款。**
`formatEditBadFee()` 的字串為 D-019 §5 釘死值，設計文件已註明「呼應 D-005 §6.2 精神、非逐字同款」（列點式 vs 問答句屬情境差異的合理分歧）。請確認實作與 D-019 §5 **字元級**一致，而非與 D-005 一致。

**5-4（design-reviewer）球種中性。**
新增文案為「已更新計費方式」「每人費用 N 元」「場地費 N 元」及新 `bad_fee` 句，均為中性用語；請依 CLAUDE.md §0 複核無特定球種用語混入。
